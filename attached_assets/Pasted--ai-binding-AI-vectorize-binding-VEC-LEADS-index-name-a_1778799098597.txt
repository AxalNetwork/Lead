type ExtractedPerson = {

  linkedin?: string;

extractPeopleFromHTML(html, sourceUrl, env):
Reduce the HTML to plain text + retained anchor URLs (strip scripts/styles, keep <a> href + text, keep headings).
Chunk into ~6KB windows (the text + a few hundred chars of surrounding context).
For each chunk, call env.AI.run("@cf/meta/llama-3.1-8b-instruct-fast", { messages, response_format: { type: "json_schema", json_schema: PERSON_ARRAY_SCHEMA }}). The system prompt: "Extract every person mentioned on this VC firm page. Return strict JSON matching the schema. Only include people clearly working at this firm. Persona must be one of: vc_partner, vc_principal, vc_analyst, advisor, operating_partner, founder, other."
Merge across chunks using nameKey (Task 8).
For each AI-extracted person, also run a verification pass: @cf/meta/llama-3.1-8b-instruct-fast with prompt "Given the page text, does the role {role} appear next to the name {name}? Answer yes/no with confidence 0-1." Anything below 0.6 confidence gets dropped.
Cache every AI call: key = sha256(model + prompt + html_chunk), store JSON response in AI_CACHE R2 bucket. 30-day TTL via lifecycle rule. Workers AI is cheap but not free; this halves the bill on re-runs.
Use the same pattern for:

3. Vectorize-powered entity resolution (apps/worker/src/dedupe/vector.ts)
Replace Task 8's exact-key dedup with vector + AI arbitration. Exact-key still runs first as a cheap pre-filter.
For every lead, firm, and company, on insert OR update, compute an embedding:
buildLeadText(lead) = "${lead.name} | ${role} | ${firm.name} | ${city}, ${country} | ${bio.slice(0,500)} | ${emails_json.map(.email).join(' ')} | ${socials_json.map(.url).join(' ')}"
Call env.AI.run("@cf/baai/bge-base-en-v1.5", { text: [buildLeadText(lead)] }) → 768-dim vector. Upsert into VEC_LEADS with id = lead.id, metadata = { name, firm_id, country, persona }.
On every new candidate person (from any scrape job), before INSERT:
Build the candidate text.
Embed it via @cf/baai/bge-base-en-v1.5.
Query VEC_LEADS.query(vector, { topK: 5, returnMetadata: true }).
For each match with score > 0.82:
Run an AI arbitration call: @cf/meta/llama-3.1-8b-instruct-fast with prompt "Given Person A: {existing JSON}. Given Person B: {candidate JSON}. Are they the same person? Output strict JSON: {match: 'yes'|'no'|'maybe', confidence: 0..1, reason: '...'}."
If match=yes && confidence>0.85 → enqueue MERGE into existing (route through Durable Object lock below).
If match=maybe or match=yes && confidence<0.85 → create a dedupe_review row (Task 8) with both AI arbitration JSONs as evidence.
If match=no → continue to next top-K result.
If no match survives → INSERT new lead and add its vector to VEC_LEADS.
Same flow for firms (vector text = name + domain + thesis + sectors + city) and companies (text = name + domain + tagline + description + founders + sectors).
This is the "when similar info is found, populate existing profile" guarantee: the moment a scraper sees a person who is semantically the same as someone already in the DB (even if name spelling, firm phrasing, or city formatting differs), we merge into the existing profile instead of creating a duplicate, and every new field gets added with full provenance.
Add a backfill job apps/worker/src/scripts/embed-all.ts that walks every row and populates the three Vectorize indexes. Run once via wrangler triggers --execution-mode=remote.
4. Durable Object merge locks (apps/worker/src/do/EntityLock.ts)
Two scrapers can hit the same person at the same time. Without a lock you race and lose fields. Use a Durable Object per {kind, id} as a serialized merge queue.
export class EntityLock {
  state: DurableObjectState;
  env: Env;
  constructor(state: DurableObjectState, env: Env) { this.state = state; this.env = env; }
  async fetch(req: Request) {
    const { op, payload } = await req.json();
    // The DO's single-threaded execution model serializes all merges for this id.
    if (op === "merge_lead") return Response.json(await mergeLeadFields(this.env, payload));
    if (op === "merge_firm") return Response.json(await mergeFirmFields(this.env, payload));
    if (op === "merge_company") return Response.json(await mergeCompanyFields(this.env, payload));
    return new Response("unknown op", { status: 400 });
  }
}
mergeLeadFields runs:
SELECT current lead row.
For each incoming field, decide: keep current (manual-edit, higher-priority provider, or newer enrich) or replace.
Union-merge emails_json, phones_json, socials_json, investor_investments-derived stats.
Write lead_history rows per changed field.
Recompute quality_score (Task 7 formula).
Re-embed and upsert into Vectorize.
Caller pattern (in pipeline, enrichment, importers):
const id = env.ENTITY_LOCK.idFromName(`lead:${leadId}`);
const stub = env.ENTITY_LOCK.get(id);
await stub.fetch(new Request("https://do/merge", { method: "POST", body: JSON.stringify({ op: "merge_lead", payload }) }));
Same for firm:${firmId} and company:${companyId}.
5. Workflows for durable enrichment (apps/worker/src/workflows/)
Replace the ad-hoc enrichment orchestrator (Task 6) with Cloudflare Workflows. Workflows give automatic retries, checkpoints, and survives Worker restarts — critical for chains that hit 10+ external APIs.
EnrichLeadWorkflow.ts:
export class EnrichLeadWorkflow extends WorkflowEntrypoint<Env, { leadId: number }> {
  async run(event: WorkflowEvent<{leadId: number}>, step: WorkflowStep) {
    const leadId = event.payload.leadId;
    const lead = await step.do("load lead", () => loadLead(this.env, leadId));
    const providers = await step.do("pick providers", () => decideProviders(this.env, lead));
    const results = [];
    for (const provider of providers) {
      const r = await step.do(`fetch ${provider}`, { retries: { limit: 3, backoff: "exponential" } }, () => callProvider(this.env, provider, lead));
      results.push(r);
      await step.sleep(`pace ${provider}`, "1 second");
    }
    const merged = await step.do("merge results", () => mergeProviderResults(results));
    await step.do("vector match", () => vectorEntityResolve(this.env, "lead", merged));
    await step.do("merge into lead via DO", () => doMerge(this.env, "lead", leadId, merged));
    await step.do("re-embed", () => embedLead(this.env, leadId));
    await step.do("recompute stats", () => recomputeInvestorStats(this.env, leadId));
    return { ok: true, fieldsUpdated: merged.changedFields };
  }
}
Same shape for EnrichFirmWorkflow (team crawl + provider enrichment + portfolio fetch) and IngestPageWorkflow (fetch → extract → resolve → merge for any scraped URL).

10. Wire-up rules (cross-cutting)
Every Worker entrypoint (fetch, queue, scheduled, Workflows) takes the same Env type.
Workers AI calls must check env.RL_AI.limit({key:"global"}) first; on rate-limit, return cached result or fall back to deterministic parser.
Every AI call writes one Analytics Engine event with purpose (extraction, embedding, arbitration, normalization, bio_summary, persona_infer, ocr, email_classify), neurons, and cache_hit.
Every Vectorize upsert is fire-and-forget from the DO merge — failures get logged but don't block the merge transaction.
The KV bindings stay only for short-lived caches: robots:{host}, enrich:{provider}:{key} (14d), profile:investor:{id} (5min). Bulk caches move to AI_CACHE R2.
