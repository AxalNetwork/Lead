Task 9 — Sector / persona / geography taxonomies + ICP segmentation
Standardize the dimensions we filter on so the dashboard segment heatmap is meaningful. Add three new tables in 060_taxonomies.sql:


























CREATE TABLE tax_sectors (
  slug TEXT PRIMARY KEY,
  label TEXT NOT NULL,
  parent_slug TEXT,
  aliases_json TEXT
);
CREATE TABLE tax_geographies (
  slug TEXT PRIMARY KEY,
  label TEXT NOT NULL,
  country_iso2 TEXT,
  region TEXT,
  kind TEXT
);
CREATE TABLE icp_profiles (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  description TEXT,
  persona_in TEXT,
  sector_in TEXT,
  geo_in TEXT,
  age_bracket_in TEXT,
  net_worth_tier_in TEXT,
  min_quality REAL,
  created_by TEXT,
  created_at TEXT DEFAULT (datetime('now'))
);
Seed tax_sectors from a JSON file at apps/worker/data/sectors.json with ~80 sectors useful to axal.vc (AI/ML, infra, fintech, climate, biotech, defense, gov-tech, web3, robotics, etc.) and tax_geographies from ISO-3166 + top 100 global metros.
Tagging: when a lead is created/enriched, run tag.ts which:
* Maps freeform firm sector text to tax_sectors slugs via the aliases_json lookup; writes back to sector_focus_json.
* Maps location strings to tax_geographies.slug and back to country_iso2 / region.
Endpoints:
* GET /api/taxonomies/sectors, /geographies — used by dashboard filters.
* GET/POST/DELETE /api/icp — CRUD on ICP profiles.
* GET /api/icp/:id/match — returns the lead list matching that ICP, with per-lead match score.
Dashboard: add a "Segments" tab with a sector × geography heatmap (counts + avg quality), and an "ICPs" page where the user defines target profiles and sees a live count + quality summary.
Acceptance criteria:
* Filtering the lead table by sector=ai_infrastructure works and returns taxonomy-mapped leads (not just exact-string matches).
