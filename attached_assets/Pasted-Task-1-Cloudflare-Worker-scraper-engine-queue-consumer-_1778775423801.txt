Task 1 — Cloudflare Worker scraper engine (queue consumer + Browser Rendering)
In apps/worker/, replace the queue consumer stub at src/index.ts:52-63 with a real scraping pipeline.
Add a Cloudflare Browser Rendering binding BROWSER to wrangler.toml and a KV binding SCRAPE_CACHE (24h TTL) so we don't re-fetch the same URL twice in a day. Add an R2 binding RAW_HTML to archive every successfully fetched page (key = sha256(url) + '/' + ISO date).
Create src/scraper/ with:
fetcher.ts — fetchPage(url, opts) that tries plain fetch first, falls back to BROWSER.launch() (puppeteer-core) when the response is < 2KB, is a 200 with a captcha keyword, or status in (403, 429, 503). Rotates user-agent from a small pool, sets Accept-Language, randomized viewport, honors a per-host rate limit stored in KV (rl:{host}).
parsers/ — one file per source type: linktree.ts, beacons.ts, crunchbase.ts, pitchbook.ts, sec-edgar.ts, opencorporates.ts, gov-registry.ts, personal-site.ts, generic.ts. Each exports parse(html, url) -> ParsedLead[]. Use cheerio (works in Workers via nodejs_compat) or linkedom.
pipeline.ts — runJob(job, env): fetch → parse → normalize → dedupe → write to D1. On error, write jobs.error and bump jobs.status='failed'. On success, set jobs.leads_found, jobs.finished_at, status='completed'.
normalize.ts — clean email (lowercase, strip plus-addressing for dedupe key only), E.164 phone, country ISO-3166-1 alpha-2, LinkedIn URL canonical form, etc.
Wire the queue consumer to call pipeline.runJob per message. Message payload shape: { jobId: number, kind: 'url'|'linktree'|'profile_list', target: string, config: {...} }.
Add a POST /api/jobs endpoint that inserts a row into jobs, sends a message to LEAD_QUEUE, and returns { jobId }. Add GET /api/jobs, GET /api/jobs/:id, POST /api/jobs/:id/cancel (cancel = set status='cancelled'; consumer must check before each page).
Add a scheduled trigger to wrangler.toml (cron = ["0 */6 * * *"]) that re-runs every sources.enabled=1 row whose last_scraped_at is older than 24h. Implement in a new src/scheduled.ts and export scheduled from index.ts.
Write a migration apps/worker/migrations/010_scraper.sql that adds: jobs.kind, jobs.target, jobs.cancelled_at, jobs.cost_ms, jobs.pages_fetched, jobs.pages_blocked, jobs.captcha_hits.
Add cheerio (or linkedom) and @cloudflare/puppeteer to apps/worker/package.json. Update tsconfig.json if needed. Run npm run typecheck and fix all errors before finishing.
Acceptance criteria:
POST /api/jobs with {kind:'url', target:'https://example.com'} returns a jobId and the consumer fetches, parses, and inserts at least the source_domain and source_url into leads.
GET /api/jobs/:id reflects status transitions queued → running → completed.
wrangler deploy succeeds; wrangler tail shows the consumer running.
