Task 14 — Firm-list importers (Airtable shares, Google Sheets, Mercury, OpenVC, NFX, Folk)
The user has 9+ public VC firm lists. The current scraper got 7 leads from them — that's because none of those URLs serve straight HTML rows; they're SPAs that hydrate via JSON APIs or require parsing embedded JSON blobs. Build dedicated importers, not generic HTML scraping.
Add apps/worker/src/scraper/parsers/firmlists/ with one file per source. Each exports importFirms(url, env) -> {firms: FirmCandidate[], totalSeen: number} where FirmCandidate matches the firms table from Task 13.
Required importers:
airtable_share.ts — Airtable share URLs of the form airtable.com/app{X}/shr{Y}/tbl{Z} (and viw{W}). Strategy: load via Browser Rendering (Task 1's BROWSER binding), wait for [data-rowid] selectors, then read the row data from window.__INITIAL_DATA__ or intercept the readSharedViewData XHR. Falls back to scrolling-and-DOM-scraping if the JSON isn't reachable. Map column headers heuristically: anything containing firm|fund|name → name, stage|round → stages_json, check|ticket|size → check size range, geo|location|region|hq → geography, thesis|focus|sector|industry → sectors/thesis, lead|follow → lead_or_co, notes|description → notes. Numeric values like "$500K-$2M" parse to a {min, max, typical} triple.
google_sheets.ts — public Google Sheets URLs (docs.google.com/spreadsheets/d/{ID}). Strategy: fetch https://docs.google.com/spreadsheets/d/{ID}/gviz/tq?tqx=out:json&gid={gid} which returns a JSONP payload usable without auth. Parse headers the same way as Airtable.
mercury.ts — mercury.com/investor-database. Strategy: SPA. Use Browser Rendering, wait for [data-test="investor-row"] (or equivalent), paginate by clicking "Load more" until exhausted, collect each row's name + linkedin + thesis + stage + check size + geo.
openvc.ts — openvc.app/search. Strategy: their public JSON endpoint at api.openvc.app/v1/search?... (or the __NEXT_DATA__ blob on the page). Paginate via the page query param. Each result has fund name, website, AUM, stage, sector tags.
nfx_signal.ts — signal.nfx.com. Login-gated. Do not implement scraping for gated pages. Instead, implement a manual-paste path: a POST /api/import/nfx/paste endpoint accepting an array of {name, url, ...} objects. Document this clearly in the file header.
folk_app.ts — app.folk.app/shared/.... Strategy: Browser Rendering, watch the /api/share/... XHR call, capture its JSON, then parse contacts.
nyc_founder_guide.ts — nycfounderguide.com/investors. Strategy: plain HTML fetch + Cheerio. Selectors against the current page structure.
versatilevc.ts — versatilevc.com/free. Strategy: page is mostly static; download the linked CSV/PDF if present, otherwise scrape the tables.
generic_csv_url.ts — fallback: if user pastes a URL ending in .csv or .tsv, fetch and parse directly with PapaParse-style logic.
generic_jsonld.ts — fallback: many list pages embed <script type="application/ld+json"> with ItemList schema. Parse that as a final resort.
Wire them into the pipeline:
Add a new job kind='firmlist' with target=URL and config={importer: 'airtable_share'|'auto'}. When auto, pick the importer by matching URL → regex.
In apps/worker/src/scraper/pipeline.ts, route kind='firmlist' to parsers/firmlists/{importer}.importFirms(target, env).
For each FirmCandidate, upsert into firms using a composite dedupe key (lower(name), domain). If a firm already exists, merge missing fields and bump last_modified.
For every firm imported, also enqueue a child kind='firm_team_crawl' job (Task 15) targeting firms.website.
Add an "Import firms from list" tab in the dashboard's Start Scrape panel (extends Task 2). Inputs: URL textarea (one URL per line) + importer dropdown (default "auto-detect"). Shows a progress strip: total seen / firms imported / firms updated / errors. POSTs to a new POST /api/import/firmlists.
Add GET /api/imports to show import-job history with per-importer breakdown.
Coverage targets (acceptance criteria):
Importing the user's Mercury URL produces > 100 firms (Mercury has 700+).
Importing the user's OpenVC URL produces > 100 firms per page.
Importing one of the Airtable share URLs produces all visible rows (>50 typical).
Each imported firm has at minimum name, domain (or website), and imported_from set.
Rerunning the same import does NOT create duplicate firms; it updates last_modified and any newly-discovered fields.
