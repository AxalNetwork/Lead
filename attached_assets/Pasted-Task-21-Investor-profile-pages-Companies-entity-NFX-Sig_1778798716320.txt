Task 21 — Investor profile pages + Companies entity (NFX Signal–style detail views & search)
Build first-class Investor Profile and Company pages with the same depth as signal.nfx.com/investors/{slug} — rich enough that hovering on an investor or company tells the user everything they need to know in one screen, and a searchable browse UI over both.
1. Companies as a first-class entity
Today firm_portfolio only holds company names. Promote companies into their own table.
Migration apps/worker/migrations/130_companies.sql:

3. Enrichment routing for investor profiles
Extend Task 6's enrichment orchestrator (apps/worker/src/enrichment/orchestrator.ts) so that running enrichment on a lead also:
Calls providers/crunchbase.ts for person.investments[] → maps to investor_investments rows, creating companies rows on the fly.
Calls providers/sec_edgar.ts for any Form D where this person is listed as related (use the person's known firms to scope the search).
Hits Wikipedia + Wikidata public APIs (en.wikipedia.org/api/rest_v1/page/summary/{slug}) — many notable investors have entries with structured Person data (birth year, education, awards, exits).
Scrapes the NFX Signal public profile page if a Brave Search query like site:signal.nfx.com/investors "{name}" returns a hit — fetches the public part via Task 5 fetcher, parses the structured blocks (sweet spot, sector focus, stage focus, notable investments).
Scrapes the investor's listed personal site for office hours, pitch form, calendly link.
Pulls podcast appearances via Listen Notes API (LISTEN_NOTES_KEY) and news mentions via NewsAPI (NEWS_API_KEY).
Each provider writes evidence to lead_history (Task 3) with change_kind='enrich' and a source_url.
4. Investor profile detail page
New page apps/site/dashboard/investors/{id}.html (route via Jekyll permalink or a single dynamic JS router). Layout, top to bottom, matching the depth of NFX Signal:
Header block:
Avatar (left, 96px circle)
Name (h1) + verified-badge if quality_score ≥ 70
Current role + firm link (clickable to firm page)
City, country
Persona pill (Venture Partner, GP, Angel)
Quick action buttons: Email, LinkedIn, Twitter, Calendly, Pitch (only render the buttons we have data for)
"Last seen on the web" timestamp
Sweet-spot strip (yellow callout): the sweet_spot sentence rendered prominently.
At-a-glance stats (six tiles):
Investments (total + lead-count)
Unicorns
Exits / IPOs
Avg check
First investment year
Last investment date
Tabs:
About — Bio, long-bio, languages, interests, education table, employment timeline.
Thesis & focus — sector_focus chips, geo_focus chips, stage_focus chips, check-size range, lead/co-invest preference, pitch-form / office-hours links, open-to-cold-pitch toggle.
Portfolio — table of investor_investments joined with companies. Columns: logo, company, sector, stage at investment, year, amount (if known), lead?, status (active/acquired/IPO), exit value. Default sort by year desc. Filters: stage, sector, outcome. Click a company → company detail page.
Stage breakdown — horizontal bar chart of investor_stats_daily.stage_breakdown_json. Bars colored by stage.
Sector breakdown — donut chart of sector_breakdown_json.
Geography — small world map highlighting countries from geo_breakdown_json.
Co-investors — table of top 10 co-investor firms with overlap count + click-through to that firm's profile.
Network — embedded relationship graph (Task 19) rooted at this person, depth=2. Filterable by edge kind.
Boards & advisory — board_seats_json + advisory_roles_json tables.
Media — podcast appearances, articles, speaking engagements, news mentions (joined from company_news where the person is mentioned).
Contact — emails_json (with verified badge), phones_json, socials_json, personal_site, office_location. PII access on this tab writes a pii_access_log row (Task 10).
History — lead_history audit trail.
Sidebar (sticky, right side):
"Find similar investors" — top 5 leads with same persona + overlapping sector_focus + similar check size.
"Path to this investor" — uses Task 19's intros endpoint to show shortest chain from the current user.
"Last enriched" + "Re-enrich" button.
Endpoint: GET /api/investors/:id/profile returns the entire denormalized profile object (lead + firm joins + investments + companies + stats + co-investors + similar + path) in one request to keep page load fast. Cache in KV at profile:investor:{id} for 5 minutes; bust on any lead_history write for that lead.
